# Subsurface Neo — Working Roadmap

This document is the working implementation schedule for **Subsurface Neo**. Neo keeps the mature Subsurface dive engine and hardware support while modernizing the user experience and adding carefully selected capabilities from SeaBirds and new Neo-specific services.

## Guiding principles

- Preserve the mature Subsurface core wherever possible instead of rewriting it.
- Keep compatibility with Subsurface data formats and libdivecomputer.
- Treat SeaBirds as a source of proven UX/product ideas and web-device transport concepts, not as a replacement backend.
- Keep native Android and Windows builds fully capable of Bluetooth/USB dive-computer downloads.
- Share as much Qt/QML/core code as practical with the future WebAssembly build.
- Never ship OAuth client secrets or provider access/refresh tokens in source or plaintext preferences.
- Maintain a clean path for continuously receiving upstream Subsurface fixes, libraries, formats and dive-computer support.

## Milestone 0 — Build & CI foundation

**Goal:** reliable reproducible Neo builds before larger feature work.

- Android Qt 6 GitHub Actions build producing an APK artifact.
- Windows Qt 6/MSVC GitHub Actions build producing an installer.
- Keep CI green on `modern-ui`.
- Establish Neo application naming/version metadata.
- Finalize Android application/package ID before Android OAuth registration.
- Establish release version convention and Git tag convention.

**Exit:** Android and Windows builds can be produced from GitHub Actions from a known Neo commit.

## Milestone 1 — Upstream Subsurface Sync & Neo Release Infrastructure

**Goal:** make Neo a maintainable fork that continuously benefits from upstream Subsurface development and can notify users when a newer Neo build is available.

### 1A. Upstream synchronization

Recommended branch policy:

- `master` — stays as close as practical to `subsurface/subsurface` upstream.
- `modern-ui` — Neo integration/development branch.
- Temporary `upstream-sync/*` branches may be generated by automation when needed.

Implement a scheduled/manual GitHub Actions workflow that:

1. Fetches the official `subsurface/subsurface` repository.
2. Detects commits not yet integrated into Neo.
3. Creates or updates a dedicated **Upstream Subsurface Sync** pull request into `modern-ui`.
4. Includes the upstream commit range in the PR description.
5. Runs Neo Android and Windows CI on the PR.
6. Never silently resolves source conflicts or overwrites Neo-specific changes.
7. Keeps one current sync PR rather than creating duplicate PRs for every upstream commit.

The sync PR is the review boundary for:

- new libdivecomputer support,
- new dive-computer models,
- library/dependency changes,
- parser/import/export improvements,
- decompression/profile fixes,
- bug fixes,
- data-model changes,
- Qt/platform compatibility changes.

Initial policy: **manual merge after green CI**. Later, conflict-free upstream sync PRs may optionally use auto-merge after sufficient test coverage exists.

### 1B. Conflict-minimizing fork architecture

To reduce future upstream conflicts:

- avoid modifying `core/`, `libdivecomputer/`, parsers and other mature upstream code unless required;
- prefer Neo adapters, QML views and provider abstractions around upstream APIs;
- document unavoidable upstream-file modifications;
- keep Neo-only files in clearly named locations where practical.

### 1C. Neo releases

Create a release workflow that can publish versioned Neo builds from Git tags/releases:

- Android APK,
- Windows installer,
- release notes/changelog,
- SHA-256 hashes,
- version/build metadata.

A release must only be advertised to applications after its required platform artifacts have completed successfully.

### 1D. Built-in update check

Add a non-blocking update service used by Android and Windows.

Behavior:

- check for a newer stable Neo release after startup without delaying application launch;
- cache the result and avoid checking excessively (target: at most approximately once per day unless the user manually checks);
- compare normalized release versions rather than commit dates;
- show a small unobtrusive notification when an update exists;
- show version, release summary and an explicit **Download Update** action;
- allow **Remind me later**;
- add **Check for updates** in Settings/About;
- allow automatic update checks to be disabled.

Initial installation behavior:

- **Windows:** notify and open/download the signed Neo installer; do not silently replace the running application.
- **Android direct APK distribution:** notify and direct the user to the official Neo release APK. If a store distribution channel is added later, use the store-supported update flow for that channel.

Security/reliability:

- only trust official Three-Cats-LSP Neo release metadata;
- verify downloadable artifacts with published hashes when Neo performs the download itself;
- never execute arbitrary URLs from untrusted update metadata;
- plan Windows code signing and stable Android release signing before public production releases.

Preferred architecture: a small versioned **Neo update manifest** generated from the release workflow, containing at least version, channel, release notes URL and platform artifact metadata. This isolates the app from GitHub API details while GitHub Releases remains the source of published builds.

**Exit:** a new upstream Subsurface change can become a reviewable Neo sync PR, and a new Neo release can notify installed Android/Windows users that an update is available.

## Milestone 4 — Modern Dive List, Search, Filters & Collections

**Goal:** make large dive logs fast to browse and organize.

### Dive list

- Modern metadata-first dive cards/list rows.
- Search.
- Sorting.
- Pagination/virtualized handling as appropriate.
- Quick filter chips.

### Filtering

Keep the mature Subsurface filter backend and provide a modern SeaBirds-inspired UI over it.

Expose practical filters including, where supported by Subsurface data:

- full-text search,
- year/month/date,
- location/country/dive site,
- dive mode,
- dive type/style,
- depth/duration ranges,
- water temperature,
- deco/NDL properties,
- gas/O2/He,
- dive computer,
- equipment,
- buddy/guide,
- tags and notes.

Advanced filters should support Subsurface comparison/range logic without making the default interface complex.

### Trips, Collections and Smart Collections

Keep Subsurface **Trips** for actual trip semantics.

Add:

- **Collections** — manually selected arbitrary dive groups.
- **Smart Collections** — saved filter rules that automatically resolve to matching dives.

Examples:

- Favourite dives.
- Training dives.
- CCR dives in Japan deeper than 30 m.
- Dives missing notes or site information.
- Dives made with a particular computer or equipment kit.

Allow **Save current filter as Smart Collection**.

**Exit:** a diver can quickly locate and organize dives without losing the power of Subsurface's existing filter engine.

**Goal:** a modern high-information dive view without unnecessary photos or permanent bulky tables.

Layout:

1. Max Depth / Dive Time / Water Temp / Mode / Gear.
2. Dive Graph.
3. Gas information / Type / Buddy.
4. Notes.

Profile graph:

- depth,
- water temperature,
- NDL/deco,
- GF99,
- optional gas and cylinder overlays,
- event/gas-switch/deco-stop markers,
- hover/tap nearest-sample inspection,
- vertical crosshair,
- floating tooltip,
- multiple dive-computer awareness where available.

Tooltip may include available values such as:

- time,
- depth,
- water temperature,
- NDL/deco,
- GF99,
- PPO2,
- pressure,
- SAC/RMV.

Show computer metadata where available:

- computer model,
- dive mode,
- decompression algorithm,
- gradient factors.

Graph controls become a collapsible descriptive checkbox panel on desktop and a mobile-friendly sheet/panel on phones.

**Exit:** Neo dive details fully replace the old presentation for normal reviewing/analysis workflows.

## Milestone 11 — Data, Export, Backup & Portability

**Goal:** make Neo data easy to share, archive, move and restore.

### Unified Export / Share

Support a modern central export workflow for the formats available/implemented in Neo, including:

- PDF Dive Report,
- human-readable plain text,
- UDDF,
- Subsurface XML,
- CSV/other useful existing Subsurface exporters.

Where the format permits, support:

- one dive,
- selected dives,
- complete log.

PDF reports should use Neo's high-quality profile/data presentation and may include:

- summary metrics,
- site/date,
- graph,
- gases/cylinders,
- computer/deco metadata,
- buddies,
- equipment,
- notes.

Before implementing a duplicate exporter, audit existing Subsurface export paths and reuse them where they already provide the required fidelity.

### Backup & Restore

Do **not** replace mature Subsurface XML storage with a SeaBirds-style JSON database.

Provide a modern user-facing workflow around Subsurface-compatible data:

- Create Local Backup.
- Restore From Backup.
- Backup inspection/summary before restore.
- Merge with current log.
- Replace current log with explicit confirmation.
- Use existing Subsurface import/deduplication machinery where appropriate.

### Neo portable backup bundle

Investigate a single-file Neo backup package such as `.subsurface-neo`, containing conceptually:

- canonical `divelog.xml`,
- `manifest.json`,
- Neo settings/metadata,
- equipment-library metadata,
- collections/smart-collection metadata,
- future optional attachments.

The XML remains the canonical dive data; Neo-specific metadata lives alongside it rather than breaking Subsurface compatibility.

**Exit:** users can export useful reports, move data between systems and safely restore a Neo library.

## Milestone 12 — Cloud Sync, Accounts, Settings & Security

**Goal:** productionize Neo cloud/account features and overall application settings.

Keep existing Subsurface Cloud support and add a provider abstraction for optional additional providers.

Planned providers:

- Subsurface Cloud,
- Google Drive App Data,
- Dropbox App Folder,
- OneDrive App Folder.

Sync model:

- one Primary Sync provider,
- optional Backup providers,
- avoid uncontrolled multi-master three-way sync until a robust conflict model exists.

OAuth/security:

- OAuth 2.0 Authorization Code + PKCE,
- no client secrets in binaries,
- secure credential storage,
- Android Keystore/encrypted local storage,
- Windows Credential Manager,
- provider disconnect/revocation,
- account identity/status UI,
- conflict and sync-state metadata.

Also complete:

- settings polish,
- release/update preferences,
- privacy/terms links,
- production OAuth readiness.

**Exit:** Neo cloud synchronization and settings are production-ready on native platforms.

# Ongoing workstream — Upstream compatibility

This is continuous and applies to every milestone, not only Milestone 1.

For every upstream sync PR:

1. inspect data-model/API changes,
2. run Android CI,
3. run Windows CI,
4. run relevant import/profile/filter tests,
5. inspect conflicts in Neo-modified upstream files,
6. update Neo adapters when upstream APIs evolve,
7. merge only when Neo behavior remains correct.

A feature is not considered complete if it makes future Subsurface upstream synchronization unnecessarily difficult without a documented reason.

# Ongoing workstream — Release readiness

For release candidates:

1. build signed/reproducible native artifacts,
2. run smoke tests,
3. generate release notes and update manifest,
4. publish GitHub Release,
5. publish hashes/metadata,
6. verify update checker detects the release from the previous stable version,
7. only then mark the release as available to users.
